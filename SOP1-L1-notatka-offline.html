Najpierw ogarnij trzy rzeczy: gdzie jest CWD, co naprawdę zwraca funkcja i kto ma zwolnić pamięć. To rozwiązuje większość problemów z L1.

Ściągi krok po kroku

Czytam katalog — przepis bez zgadywania

  1. Otwórz DIR *dir = opendir(path); NULL oznacza błąd.
  2. Przed każdym readdir ustaw errno = 0.
  3. Jeżeli wynik to NULL, od razu sprawdź errno: zero = koniec, niezero = błąd.
  4. d_name to tylko nazwa. Dla opendir("dane") budujesz "dane/" + d_name. Samo opendir nie zmienia CWD.
  5. Do rozpoznawania linków używaj lstat. Do rozmiaru celu linku użyj stat.
  6. Przy rekurencji pomijaj . i ... Nie ufaj kolejności wpisów ani niestandardowemu d_type.
  7. Zamknij closedir. Wskaźnik z readdir jest pożyczony: nie rób free(dp), kopiuj nazwę jeśli chcesz ją zatrzymać.
schemat-katalog.c
Pobierz
DIR *dir = opendir(path);              // path np. "library/1"if (!dir) ERR("opendir");for (;;) {    errno = 0;                         // nie tylko raz przed pętlą!    struct dirent *dp = readdir(dir);    if (!dp) {                         // NULL: koniec albo błąd        if (errno) ERR("readdir");        break;    }    if (!strcmp(dp->d_name, ".") || !strcmp(dp->d_name, "..")) continue;    char *full = join_paths(path, dp->d_name); // nasza funkcja; wynik malloc    if (!full) ERR("join_paths");    struct stat st;    if (lstat(full, &st)) ERR("lstat");  // lstat widzi sam symlink    if (S_ISREG(st.st_mode)) { /* zwykły plik */ }    free(full);                        // nie free(dp->d_name)!}if (closedir(dir)) ERR("closedir");

To fragment do wklejenia do programu z nagłówkami, makrem ERR i funkcją join_paths. Pełne rozwiązania niżej sprzątają także przy błędach; tutaj ERR kończy proces.

Czytam plik po liniach — i nie gubię ostatniej

getline przydziela lub powiększa bufor. Oddaje liczbę odczytanych bajtów, zwykle z , ale bez końcowego zera. Ostatnia linia może nie mieć nowej linii.

schemat-linie.c
Pobierz
FILE *fp = fopen(path, "r");if (!fp) ERR("fopen");char *line = NULL;                      // getline może zaalokować pamięćsize_t capacity = 0;ssize_t n;while ((n = getline(&line, &capacity, fp)) != -1) {    if (n > 0 && line[n - 1] == '\n') line[--n] = '\0';    if (n > 0 && line[n - 1] == '\r') line[--n] = '\0';    char *colon = strchr(line, ':');    if (!colon) continue;              // brak separatora: pomijamy linię    *colon = '\0';                     // line jest teraz kluczem    char *value = colon + 1;           // pożyczony fragment line    if (!strcmp(line, "title")) {        printf("title: %s\n", value);  // własne \n, niezależne od pliku        // Jeśli value ma żyć po kolejnym getline: zrób strdup(value).    }}if (ferror(fp)) ERR("getline");free(line);                            // tylko właściciel całego bufora!if (fclose(fp)) ERR("fclose");

Brak pola i błąd odczytu to dwie różne sprawy. W pełnym parserze sprawdzamy również zakończenie getline bez EOF (np. problem alokacji). strchr nie tworzy nowego napisu, tylko zwraca adres wewnątrz istniejącego.

CWD, rekurencja i pełna ścieżka

CWD = bieżący katalog procesu. Ścieżka względna użyta w fopen, lstat, opendir jest interpretowana od CWD. getcwd zapisuje ścieżkę w Twoim buforze; chdir zmienia CWD całego procesu.

Masz dwie metody skanowania: (1) nie zmieniasz CWD i sklejasz ścieżki — tak robi poprawiony listing i Biblioteka; (2) zapisujesz CWD, wchodzisz przez chdir, skanujesz ".", wracasz przed kolejnym argumentem — tak działa l1-2.c. Nie mieszaj tych metod w połowie funkcji.

W rekurencji używamy lstat i wchodzimy tylko w S_ISDIR. Pominięcie symlinków zapobiega np. pętli library/loop → .. Każde wywołanie rekurencyjne ma własny DIR*. W tej wersji maksymalna głębokość jest ograniczona stosem i liczbą otwartych katalogów.

A nftw / ftw z nagłówka startowego?

nftw(path, callback, maxfd, FTW_PHYS) może przejść drzewo za Ciebie. Callback dostaje ścieżkę, dane stat, flagę typu i strukturę FTW (m.in. base/level). Zwracając 0 kontynuuje. FTW_PHYS oznacza brak podążania za symlinkami. ftw ma prostszy callback i mniej kontroli. Wystarczy znać jedną metodę — tutaj wybraliśmy jawną rekurencję, żeby widzieć opendir/readdir/closedir.

Podstawa: Materiał SOP. Objaśnienia i poprawione rozwiązania są autorskie.

Uprawnienia, usuwanie i buforowanie — szybka pomoc

  • mkdir(path, 0777) tworzy katalog; końcowe prawa ogranicza umask. Dla katalogu x oznacza możliwość przejścia przez niego; r pozwala czytać listę nazw.
  • chmod(path, 0644) ustawia prawa. Korekta uproszczenia w materiale: zwykle trzeba być właścicielem pliku albo mieć odpowiednie uprawnienia uprzywilejowane; samo prawo zapisu do pliku nie wystarcza.
  • access(path, R_OK) to sprawdzenie, nie gwarancja późniejszego otwarcia. Najważniejszy jest wynik samego fopen/open.
  • unlink(path) usuwa nazwę, a nie „czyści zawartość”. Dane żyją, dopóki istnieje dowiązanie twarde lub otwarty deskryptor. Usunięcie symlinku nie usuwa celu.
  • printf na terminalu zwykle buforuje liniami, po przekierowaniu — blokami. Do debugowania użyj fprintf(stderr,...). Sprawdzaj fflush i fclose.

Tutorial każdej funkcji

opendir() — jak użyć

Nagłówek: <dirent.h>

DIR *opendir(const char *path)

Otwórz katalog, zanim zaczniesz odczyt wpisów. Argument to ścieżka katalogu; wynik zachowaj w DIR*.

Argumenty i wynik: Otwiera strumień katalogu. Sukces: DIR*, błąd: NULL. Zamknij closedir.

przyklad-opendir.c
Pobierz
DIR *d = opendir("library");if (d == NULL) ERR("opendir");// Po zakończeniu: closedir(d).

Nie zmienia CWD; nazwa z readdir nie jest pełną ścieżką.

readdir() — jak użyć

Nagłówek: <dirent.h>

struct dirent *readdir(DIR *dir)

Podaj otwarty DIR*, pobierz jeden wpis i dopiero wtedy korzystaj z d_name. Powtarzaj aż do NULL.

Argumenty i wynik: Oddaje kolejny pożyczony wpis; NULL to EOF lub błąd (errno).

przyklad-readdir.c

errno = 0;struct dirent *e = readdir(d);if (!e && errno) ERR("readdir");if (e) printf("%s\n", e->d_name);

errno=0 tuż przed każdym wywołaniem. Nie free(dp); d_name kopiuj, jeśli potrzebujesz na później.

stat() — jak użyć

Argumenty i wynik: Wypełniają Twoją strukturę; 0 sukces, −1 błąd. stat śledzi końcowy symlink, lstat opisuje link; fstat otwarty fd.

getopt: zbieraj opcje, potem działaj

"p:o:" oznacza: -p wymaga wartości, -o wymaga wartości. optarg wskazuje aktualną wartość. optind jest indeksem pierwszego nieprzetworzonego argumentu. opterr=0 wyłącza automatyczne błędy getopt, optopt wskazuje problematyczną literę.

W końcowej wersji zadania 1: wiele -p jest OK, drugie -o jest błędem, nieznana opcja i argument pozycyjny dają usage na stderr. Walidujemy całość przed otwarciem wyjścia — zły zestaw opcji nie powinien skasować treści pliku wynikowego.

Parser: naprawy w kolejności, w której warto je zrobić

  1. argc: przed użyciem argv[1] wymagaj argc==2.
  2. Usuń oba free(znajdz): wskaźnik jest pożyczony ze środka linia.
  3. Zakończ reszta: po kopiowaniu zrób reszta[ind]='\0';, dopiero potem strcspn. Albo w ogóle nie kopiuj na VLA: rozdziel oryginalną linię przy dwukropku.
  4. Własny LF: po usunięciu końca linii wypisuj printf("%s: %s\n",...).
  5. Sprzątanie: free(linia) także przed return 0. Sprawdź błąd odczytu po getline.

  7. Na etapy 2–4: parser ma zwrócić strukturę, nie tylko wydrukować. Jedno przejście po pliku, osobne strdup dla author/title/genre.

Zadanie 1 — listing

Zadanie 1 — umowa programu i etapy

Program robi listing katalogów: nazwa każdego obiektu i jego rozmiar. -p katalog może wystąpić wielokrotnie; -o plik najwyżej raz. Bez -o piszemy na stdout. Zły katalog zgłaszamy na stderr i przechodzimy do następnego.

  1. Listing CWD, nazwy, stdout.
  2. Dodaj rozmiary przez lstat.
  3. Dodaj wiele -p (na tym etapie treść pozwala ignorować inne opcje).
  4. Dodaj -o i wybór FILE*.
  5. Końcowa walidacja: nieznane opcje, argumenty pozycyjne, powtórzone -o → usage.

Decyzje w poprawionej wersji: nie pokazujemy . i .., pokazujemy pozostałe obiekty i pliki ukryte; brak -p oznacza CWD również przy -o. lstat pokazuje rozmiar samego symlinku. Po problemie z katalogiem kontynuujemy inne ścieżki, ale końcowy kod wyjścia to failure.

Jeśli plik wyjściowy leży w listowanym katalogu, sam pojawi się na liście; jego rozmiar podczas zapisu może zależeć od buforowania. Do przewidywalnego pokazu wybierz wyjście poza listowanym katalogiem.

Etap 1 — struktura metadanych i parser

Metadata ma trzy wskaźniki do napisów. NULL oznacza brak pola. Wartości muszą mieć własną pamięć: bufor getline jest używany ponownie, więc zapisujemy strdup(value). Po użyciu zwalniamy każde pole.

  1. Wyzeruj strukturę, otwórz plik.
  2. Czytaj linie; usuń LF i ewentualnie CR. Nie tnij ostatniego znaku, jeśli to nie LF.
  3. Znajdź pierwszy dwukropek. Wpisz w niego NUL — teraz masz dwa napisy w jednym buforze.
  4. Porównaj klucz dokładnie przez strcmp. „uthor” to inny klucz niż „author”.
  5. Skopiuj potrzebną wartość przez strdup. Nieznane klucze i linie bez dwukropka pomiń.
  6. Po EOF sprawdź zakończenie odczytu, free(line), fclose. Zwróć strukturę do main.
  7. Wypisz pola zawsze w kolejności author/title/genre i zawsze z własnym LF.

Przyjęta polityka niejednoznacznych danych: ostatni powtórzony klucz wygrywa, pusta wartość jest traktowana jako brak, linia z NUL w środku to błąd; nie obcinamy spacji wartości. Przykładowy incipit ma dalsze linie bez dwukropka — pomijanie ich jest potrzebne.

Etap 4 — doczytaj cały rekord przez readv

readv zwraca sumę odczytanych bajtów, nie liczbę struktur. Pojedyncze wywołanie nie musi dać 68. Jeśli zwróci 6, masz całe size i pierwsze 2 bajty title. Następne wywołanie ma czytać do title+2 i żądać jeszcze 62 bajtów.

  1. Wyzeruj rekord; ustaw dwa iovec.
  2. readv == −1 i EINTR → ponów. Inny błąd → zakończ kontrolę.
  3. readv == 0 przed ukończeniem rekordu → baza urwana.
  4. Po dodatnim wyniku omiń całkowicie wypełnione bufory. W bieżącym przesuń iov_base i zmniejsz iov_len.
  5. Powtarzaj, aż oba bufory są pełne. title[64] nadal ma zero.
